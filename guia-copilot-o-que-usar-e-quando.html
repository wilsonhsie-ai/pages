Microsoft 365 Copilot: o que usar e quando?

A mesma tarefa normalmente funciona em várias ferramentas. Este guia indica qual é a mais adequada e por quê.
💡

Este guia é uma recomendação e orientação

Quase todas as tarefas podem ser resolvidas com mais de uma ferramenta. Aqui sugerimos a opção mais conveniente e explicamos o motivo, mas a decisão final depende do seu contexto, das suas permissões e da sua forma de trabalhar. Use como ponto de partida e adapte a cada situação.

Regra prática um aplicativo para UM arquivo · um agente para UMA tarefa repetida · Copilot Cowork para TODO um processo.

Copilot Chat é a porta de entrada: a partir do chat você menciona agentes (@) e até pode programar instruções que se repetem sozinhas.

No aplicativo significa dentro do documento aberto, em modo de edição. Agente da Microsoft: já pronto para usar (Researcher, Analyst, Facilitator…). Agente · Agent Builder: você cria para uma tarefa repetida.

Notebooks se destaca quando você junta várias fontes (arquivos, notas, links) em um mesmo caderno e quer perguntar ou criar sempre com esse contexto fixo; para algo de um único arquivo, melhor no aplicativo.

Scout · Autopilot trabalha sozinho e de forma contínua em segundo plano: use-o para acompanhamento permanente que age por você. Para um processo que você dispara de ponta a ponta, use o Copilot Cowork.

Copilot Cowork já está disponível de forma geral (GA). Scout · Autopilot segue em Frontier (acesso antecipado) e pode mudar.

✓

Antes de criar seu próprio agente, valide nesta ordem

Criar um agente é o último recurso, não o primeiro.
Passo 1 · o mais simples

Um prompt salvo ou programado?

Se uma boa instrução repetível resolve a tarefa, use-a. Você pode salvá-la e reutilizá-la, ou programá-la para que execute sozinha. Não precisa criar nada.

Passo 2 · reutilize

Já existe um agente da Microsoft?

Revise os agentes prontos para usar (Researcher, Analyst, Facilitator, Forms, Project Manager…). Se um deles cobre a tarefa, use-o como está.

Passo 3 · último recurso

Só então, crie com o Agent Builder

Se nenhum prompt nem agente da Microsoft resolve a tarefa, crie o seu próprio agente com o Agent Builder para repetir o processo com o seu critério.

Regra prática Prompt salvo ou programado → Agente da Microsoft → (somente se nada se aplicar) seu próprio agente com o Agent Builder.

Define-se ao criar o agente e quem o usa pode mudá-lo. Com @menção não se aplica o modo padrão.

Agentes especializados — trazem o próprio modelo de raciocínio; no Researcher você escolhe o modelo e, no Frontier, o modo (Critique ou Council).
Researcher
Você escolhe o modelo de raciocínio: OpenAI Deep Research (padrão) ou Claude (Sonnet / Opus), se o seu administrador habilitar a opção.
Analyst
Modelo otimizado para analítica. Executa Python ao vivo sobre os seus dados e você pode ver o código que roda.
Modo Critique FRONTIER
No Researcher: um modelo redige e outro revisa e refina o relatório (fontes confiáveis, completude e citações rigorosas). É o modo padrão com Auto. Ideal quando você precisa de um único relatório confiável, pronto para compartilhar.
Modo Council FRONTIER
No Researcher: vários modelos (GPT e Claude) respondem em paralelo e um terceiro os compara, mostrando onde coincidem, onde divergem e o que cada um agrega. Ideal para contrastar perspectivas antes de decidir.

Computer use — opção que permite ao agente usar o navegador e apps como você (clicar, navegar, preencher formulários) para tarefas que não se resolvem só conversando; sempre dentro das suas permissões.

Regra prática Researcher: deixe em Auto (usa Critique) quando quiser um único relatório confiável e pronto para compartilhar; mude para Council quando quiser contrastar várias perspectivas (GPT e Claude) antes de decidir.

Regra prática No chat, deixe em Auto; mude para Think Deeper em tarefas que exigem análise ou para Deep Work quando precisar de ferramentas premium. Escolha um modelo específico (Opus 5 ou GPT 5.6) apenas se tiver uma preferência clara.
